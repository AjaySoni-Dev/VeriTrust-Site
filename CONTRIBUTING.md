## Development Guidelines

This is a private collaborative repository.

Please keep contributions:

- modular
- maintainable
- consistent with the current architecture
- aligned with the project direction

Avoid:

- unnecessary dependencies
- unrelated commits
- unreviewed large architecture rewrites
- inconsistent formatting

---

## Branch Naming

Use meaningful branch names.

Examples:

```text
feature/dynamic-routing
feature/template-engine
fix/auth-flow
refactor/render-system
```

---

## Commit Format

Use clean and descriptive commit messages.

```text
feat: add template rendering logic
fix: resolve deployment issue
refactor: simplify route handling
docs: update architecture notes
```

## Security

Do not commit:

- API keys
- environment variables
- private credentials
- internal infrastructure details

> [!WARNING]
> Sensitive configuration or infrastructure details should never be pushed to the repository.
