Documentation

VeriTrust platform guide.

VeriTrust currently provides three signed-in web checks: image deepfake scoring, phishing-message review, and URL-string analysis. Results normalize model output into a verdict, confidence, risk level, indicators, and an explicit limitation notice.

Use each result as decision support. It can prioritize a manual review, but it cannot establish authenticity, malicious intent, legal responsibility, or safety.

Common Use Cases

  • Review supported face images for possible synthetic-media signals before a human examines the source and context.
  • Check suspicious emails, SMS messages, links, or internal reports before employees engage with them.
  • Provide a repeatable first-pass signal for moderation, security operations, and trust-and-safety review queues.
  • Create a simple review path for non-technical teams that need a clear result without reading raw model output.

Image Checks

Image Check sends a supported image to the selected real-versus-synthetic classifier. It accepts JPG, PNG, WEBP, or BMP files up to 4 MB; it does not perform a full visual-forensics examination.

  • Use a clear face image that you are authorized to process.
  • Optional Crop Face uses the configured external crop service. If no crop is available, analysis continues with the original image.
  • Compare the result with the original context before taking action.
  • For sensitive cases, keep a record of the source, review time, and the final human decision.

Message Checks

Message Check accepts 8 to 12,000 characters of email, SMS, URL, or suspicious text. It combines the selected phishing model score with implemented language, credential, payment, sender, and link indicators.

  • Include sender text, link text, and call-to-action wording when available.
  • Avoid submitting passwords, one-time codes, payment details, or private customer records.
  • Treat urgent payment requests, credential prompts, and unusual login links as higher priority for manual review.
  • Use the result to decide whether to block, escalate, educate the user, or request more information.

Link Intelligence

Link Intelligence sends the normalized URL string to the available classifier and combines that output with deterministic URL-pattern checks. The current version does not fetch webpages, resolve shortened links, or follow redirects.

  • Submit only http:// or https:// URLs.
  • If a message contains multiple URLs, VeriTrust analyzes the first URL and returns the extracted URL list.
  • Indicators include shorteners, IP-address URLs, punycode patterns, suspicious TLDs, missing HTTPS, login/KYC/payment terms, credential terms, brand impersonation patterns, redirect parameters, embedded URLs, and random-looking tokens.
  • Use official websites, verified apps, or direct support channels to confirm suspicious links.

Privacy

Submitted image, message, and URL content is processed by the configured inference provider. Optional face cropping also sends the image to the configured crop service. Submit only content you are authorized to process.

  • Submit only the image or text required for the check.
  • Remove passwords, access codes, customer identifiers, and financial details before review.
  • Web scan metadata, results, model runs, and limited text previews can be stored in the active Supabase workspace.
  • Follow your organization's retention, consent, and incident-response policies.

Security

VeriTrust should be used as part of a broader security process that includes access control, user education, escalation paths, and audit-friendly workflows.

  • Use strong account credentials and avoid shared logins.
  • Escalate high-risk results to your security or trust-and-safety owner.
  • Do not rely on a single score for account bans, employee discipline, or legal decisions.
  • Review suspicious content in a safe environment and avoid opening unknown links directly.

Account Flow

Supabase Auth sessions protect every page except the landing and authentication pages. A default workspace is created or repaired for an authenticated user when the production schema and service role are configured.

  • Use the Auth page for email/password sign-in, account creation, email confirmation, and password recovery.
  • Use the Dashboard pages for workspace usage, saved scans, API keys, billing status, and profile settings.
  • Completed web checks are recorded against the active workspace when persistence succeeds.
  • External API v1 calls record usage but do not create dashboard scan-history records in the current implementation.

Understanding Results

VeriTrust presents a simple verdict, a confidence value, and a risk level. These signals are intended to make review faster and more consistent.

  • Verdict: The most likely classification for the submitted content.
  • Confidence: How strongly the model score supports the verdict. Strong confidence is not proof.
  • Confidence band: Weak, Moderate, or Strong, based on the reported confidence score.
  • Risk: Low, Medium, High, or Critical, used for triage and escalation priority.
  • Indicators: Rule-based or model-reported signals that explain why content may need attention.

Phishing checks combine model score with deterministic indicators such as urgency, credential requests, OTP or password language, payment wording, account blocking pressure, short links, suspicious domains, attachments, sender identity, and contact methods.

Link Intelligence checks combine URL classifier output with deterministic URL indicators. It does not claim domain age, live reputation, blocklist status, or confirmed maliciousness.

Deepfake checks are based on model score output. VeriTrust does not claim visual forensic findings such as lighting inconsistency or texture artifacts unless a model explicitly provides that evidence.

Fallback behavior differs by check: image review tries the alternate image model; phishing can fall back to another model and then a local indicator review; link review can fall back to local URL-pattern analysis. Result metadata identifies fallback use.

False positives and false negatives are possible. When a result is unclear, collect more context, compare against trusted sources, and route the case to a human reviewer.

Reports and Exports

Successful web checks expose report JSON containing the available scan ID, scan type, date, model metadata, summary, scores, evidence or indicators, extracted entities or URL details when applicable, and a disclaimer.

  • Download JSON reports for audit trails or internal case notes.
  • Use Print / Save as PDF for lightweight PDF exports from the browser.
  • Copy the result summary when you need a short escalation note.
  • Saved dashboard scans can be viewed, downloaded, and printed from scan history.

Reports are AI-assisted assessments. They should support review workflows, not replace manual verification for high-impact decisions.
